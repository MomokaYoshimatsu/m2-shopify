# Git Workflow Rules

## Start Of Day

- 最初に `AGENTS.md` を読む。
- `docs/codex-handoff.md` があれば最優先で読み、あわせて `docs/work-log-*.md` の最新ファイルを確認する。
- `git status --short --branch` で現在ブランチと作業状態を確認する。
- タスクに関係する `docs/agent-rules/*.md` を読む。
- 作業ログがない場合はユーザーに伝え、Git履歴や差分から状況を確認する。

## Branch Rules

- `main` では直接作業しない。
- `develop` では直接実装、ファイル編集、commit、pushしない。
- `shopify theme dev` などローカル変更を外部環境へ同期するプレビューサーバーが起動中の場合、ブランチ切り替え、pull、checkout、rebase、mergeの前に必ず停止する。
- 作業前に必ず `develop` へ移動し、`origin/develop` の最新状態を取得する。
- `develop` は最新化と作業ブランチ作成の起点としてのみ使う。
- 実装・調査でファイルを変更する前に、必ず `origin/develop` 起点の新しい作業ブランチを作成する。
- `git status --short --branch` で現在ブランチが `develop` の場合は、実装に入らず作業ブランチを作成して切り替える。
- worktreeを使う場合も、最新 `origin/develop` 起点で新しい作業ブランチを作成する。
- worktree作成時は原則 `git worktree add <path> -b codex/<作業内容> origin/develop` を使う。
- ブランチ名は `codex/<作業内容>`、`feature/<作業内容>`、`fix/<作業内容>`、`chore/<作業内容>` の形式にする。
- ブランチ作成前にユーザーの未コミット変更がある場合は、内容を失わない方法で保護し、無断でstash、破棄、上書きしない。
- `develop` はテーマID `187246870819` の下書きテーマへGitHub連携されているため、`develop` への反映がShopify側へ同期される前提で差分を確認する。

## Wrong Branch Recovery

- 作業中に現在ブランチが `develop` または `main` だと分かった場合は、追加編集を停止する。
- 未コミット差分を破棄・stash・別ブランチへ移動する前に、変更者と内容を確認する。
- Codex自身の変更だけで安全に分離できる場合は、最新 `origin/develop` 起点の作業ブランチへ移す。
- ユーザー変更との区別がつかない場合や競合する場合は、現状を報告してユーザー判断を待つ。
- `develop` や `main` へ誤って入った変更を自己判断でpushしない。

## Commit And Push

- 作業中はこまめにコミットしてブランチにpushする。
- commitとpushは作業ブランチでのみ行う。
- Codexは関連する変更だけをステージする。
- コミットメッセージは日本語で変更内容を短く要約する。
- ユーザーから明示的に「コミットしないで」と指示された場合のみ、コミットしない。
- コミット後は作業ブランチを `origin` へpushする。
- commit前に `git diff` と `git diff --cached` を確認し、秘密情報、テーマエディター由来の不要差分、タスク外の変更を含めない。

## PR

- PRは1タスク1PR。
- PRはタスク完了後、ユーザーがOKを出したときだけ作成する。
- PRは必ず `作業ブランチ -> develop` の向きで作成する。
- ユーザーから明示的にドラフト指定がない限り通常PRとして作成する。
- `main` へ直接push、直接mergeしない。
- PRタイトルは短く具体的な日本語にする。
- ユーザーが目視確認でOKを出す前にPRを作成しない。
- PR本文には以下を含める。
  - 変更内容
  - 変更したファイル
  - 確認したこと
  - Shopify管理画面で追加対応が必要なこと
  - 懸念点

## Task Completion Checklist

1. `git status --short` で変更ファイルを確認する
2. 必要に応じてテストまたはビルド確認を行う
3. 変更内容を要約する
4. 未コミットの関連変更があればコミットしてpushする
5. `AGENTS.md` の完了手順に従い、`shopify theme dev` でローカルプレビューを起動する。省略指示がある場合は理由を報告する
6. PR前プレビューではGitHub連携済みの固定検証テーマ `187246870819` を同期先にしていないことを確認する
7. 変更箇所をユーザーが確認できるlocal preview URLとShopify preview URLを提示する
8. ユーザーが明示的にプレビュー不要またはPR作成優先を指示しない限り、表示変更の確認を飛ばしてPRを作成しない
9. ブランチ切り替えや別タスクへ移る前に、起動中のプレビューサーバーを停止する
10. ユーザーに目視確認を依頼するときは、プレビューURLだけで済ませず、以下をまとめて提示する
    - タスクIDとタスク名
    - タスク内容と今回の変更要約
    - 確認するURL/ページ/画面
    - 具体的な確認箇所
    - PC/SPや確認幅など、必要な確認観点
    - ユーザーOK後にPR作成へ進むこと
11. ユーザーがOKを出したらPRを作成する
